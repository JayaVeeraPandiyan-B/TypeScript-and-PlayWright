
# MANUAL TESTING – QA THEORY INTERVIEW ANSWERS

**1. What is software testing and why is it important?**

* Software testing is the process of verifying whether an application works as expected and meets business requirements.

* It is important because it helps identify defects, improves product quality, increases customer satisfaction, and reduces production issues.

---

**2. Explain STLC and SDLC phases.**

* SDLC (Software Development Life Cycle)

 1. Requirement Gathering
 2. Planning
 3. Design
 4. Development
 5. Testing
 6. Deployment
 7. Maintenance

* STLC (Software Testing Life Cycle)

 1. Requirement Analysis
 2. Test Planning
 3. Test Case Design
 4. Test Environment Setup
 5. Test Execution
 6. Defect Reporting & Tracking
 7. Test Closure

---

**3. Difference between verification and validation.**

| Verification                                  | Validation                                  |
| --------------------------------------------- | ------------------------------------------- |
| Checks whether the product is built correctly | Checks whether the correct product is built |
| Process-oriented                              | Product-oriented                            |
| Done before execution                         | Done after execution                        |
| Example: Review documents                     | Example: Execute test cases                 |

---

**4. Difference between bug, defect, error, and failure.**

* Error → Mistake made by developer.
* Defect/Bug → Issue found in application.
* Failure → Application behaves unexpectedly during execution.

* Example: Developer writes wrong logic (error) → wrong output in app (defect/bug) → system crashes during usage (failure).

---

**5. Explain defect/bug life cycle.**

 1. New
 2. Assigned
 3. Open
 4. Fixed
 5. Retest
 6. Verified
 7. Closed

* Possible additional states:

  * Reopened
  * Deferred
  * Rejected

---

**6. Difference between severity and priority with examples.**

* Severity

  * Impact of the defect on application functionality.

* Priority

  * Urgency to fix the defect.

* Example:

  * Login button not working → High Severity, High Priority
  * Typo in company logo → Low Severity, High Priority

---

**7. Difference between Smoke, Sanity, Regression, Retesting, and Ad-hoc testing.**

| Testing Type       | Purpose                                       |
| ------------------ | --------------------------------------------- |
| Smoke Testing      | Checks basic critical functionalities         |
| Sanity Testing     | Verifies specific functionality after changes |
| Regression Testing | Ensures existing features still work          |
| Retesting          | Verifies fixed defect                         |
| Ad-hoc Testing     | Random testing without test cases             |

---

**8. Difference between functional and non-functional testing.**

* Functional Testing

  * Checks application features and business logic.

  * Example: Login functionality

* Non-functional Testing

  * Checks performance, security, usability, etc.

  * Example: Page load speed

---

**9. Difference between white-box, black-box, and grey-box testing.**

| Type      | Description                        |
| --------- | ---------------------------------- |
| Black-box | Tester does not know internal code |
| White-box | Tester knows code and logic        |
| Grey-box  | Partial knowledge of code          |

---

**10. Explain compatibility, exploratory, load, stress, volume, and performance testing.**

 * Compatibility Testing → Checks application on different browsers/devices/OS.
 * Exploratory Testing → Simultaneous learning and testing.
 * Load Testing → Checks behavior under expected users.
 * Stress Testing → Checks system beyond limits.
 * Volume Testing → Tests with huge data.
 * Performance Testing → Measures speed, stability, responsiveness.

---

**11. What is regression testing and how do you select regression test cases?**

* Regression testing ensures existing functionalities are not affected after new changes.

* Regression test cases selection:

  * Critical business flows
  * Frequently used features
  * Previously failed test cases
  * High-risk areas
  * Integration-related modules

---

**12. Explain alpha and beta testing.**

* Alpha Testing

  * Done internally by organization before release.

* Beta Testing

  * Done by real users in real environment before final release.

---

**13. What is Unit Testing and who performs it?**

* Unit testing tests individual components or methods of application.

* Usually performed by developers.

---

**14. What is UI testing?**

* UI testing verifies the look and feel of the application such as:

  * Buttons
  * Alignment
  * Fonts
  * Colors
  * Navigation
  * Responsiveness

---

**15. What are negative test cases?**

* Negative test cases verify how the application behaves with invalid input.

* Example: Entering alphabets in phone number field.

---

**16. Explain Boundary Value Analysis and Equivalence Partitioning.**

* Boundary Value Analysis (BVA)

  * Tests boundary values.

* Example:
  * If range is 1–100:
  * Test → 0,1,100,101

* Equivalence Partitioning (EP)

  * Divides input into valid and invalid groups.

* Example:   
  * Age 18–60:
  * Valid partition → 18–60
  * Invalid partition → below 18 and above 60

---

**17. What is Traceability Matrix (RTM)?**

* RTM maps requirements with test cases to ensure all requirements are covered.

* It helps in:

   * Requirement coverage
   * Tracking missing test cases
   * Change impact analysis

---

**18. What is Test Plan and what are its components?**

* Test Plan is a document describing testing scope, objectives, and approach.

* Components:

  * Scope
  * Objectives
  * Test strategy
  * Resources
  * Schedule
  * Risk
  * Entry/Exit criteria
  * Deliverables

---

**19. Difference between Test Strategy and Test Plan.**

| Test Strategy            | Test Plan              |
| ------------------------ | ---------------------- |
| High-level document      | Detailed document      |
| Organization-level       | Project-level          |
| Defines overall approach | Defines execution plan |

---

**20. What are Entry and Exit Criteria?**

* Entry Criteria

* Conditions required before testing starts.

* Example:

  * Build available
  * Environment ready

* Exit Criteria

* Conditions required before testing ends.

* Example:

  * Critical defects closed
  * Test execution completed

---

**21. What are test deliverables?**

* Documents shared during testing process.

* Examples:

  * Test Plan
  * Test Cases
  * RTM
  * Defect Reports
  * Test Summary Report

---

**22. What is test scenario vs test case vs test script?**

| Type          | Description              |
| ------------- | ------------------------ |
| Test Scenario | High-level functionality |
| Test Case     | Detailed testing steps   |
| Test Script   | Automation code          |

* Example:

  * Scenario → Verify login
  * Test Case → Enter username/password and click login
  * Script → Selenium/Playwright automation code

---

**23. What are the key fields in a defect report and test case document?**

* Defect Report Fields

  * Defect ID
  * Summary
  * Steps to reproduce
  * Expected result
  * Actual result
  * Severity
  * Priority
  * Status

* Test Case Fields

  * Test Case ID
  * Scenario
  * Preconditions
  * Steps
  * Test Data
  * Expected Result
  * Actual Result
  * Status

---

**24. How do you decide when testing is enough?**

* Testing is enough when:

  * All critical test cases are executed
  * Major defects are fixed
  * Requirements are covered
  * Exit criteria are met
  * Risk is acceptable

---

**25. What are Agile ceremonies?**

1. Sprint Planning
2. Daily Standup
3. Sprint Review
4. Sprint Retrospective
5. Backlog Refinement

---

**26. Explain Scrum vs Kanban.**

| Scrum                 | Kanban          |
| --------------------- | --------------- |
| Time-based sprint     | Continuous flow |
| Fixed sprint duration | No fixed sprint |
| Roles defined         | Flexible roles  |
| Sprint backlog        | Kanban board    |

---

**27. What is Definition of Done (DoD)?**

* Definition of Done is a checklist that defines when a task/user story is considered complete.

* Example:

  * Code completed
  * Testing completed
  * No critical bugs
  * Documentation updated

---

**28. What is EPIC in Agile?**

* An EPIC is a large requirement or feature that can be divided into smaller user stories.

* Example: E-commerce payment module.

---

**29. Explain 3 Amigos concept.**

* 3 Amigos discussion involves:

  * Business Analyst
  * Developer
  * Tester

* They discuss requirements to avoid misunderstandings before development starts.

---

**30. What are roles and responsibilities of QA engineers?**

* Understand requirements
* Create test cases
* Execute tests
* Report defects
* Perform regression testing
* Ensure quality standards
* Collaborate with developers and BA

---

**31. How do you handle ambiguous requirements?**

* Discuss with BA/Product Owner
* Ask clarifying questions
* Analyze business flow
* Document assumptions
* Get confirmation before testing

---

**32. How do you handle critical bugs before release?**

* Immediately inform stakeholders
* Provide detailed defect information
* Perform impact analysis
* Retest after fix
* Suggest release hold if necessary

---

**33. How do you convince developers regarding valid defects?**

* Provide clear reproduction steps
* Share screenshots/logs/videos
* Explain business impact
* Refer requirement documents
* Maintain professional communication

---

**34. What are good tester qualities?**

* Analytical thinking
* Attention to detail
* Communication skills
* Curiosity
* Patience
* Domain knowledge
* Problem-solving ability

---

**35. Which test cases should not be automated?**

* Frequently changing features
* One-time test cases
* UI-heavy unstable features
* Exploratory testing
* CAPTCHA-related scenarios

---

**36. Explain web application vs client-server application testing.**

| Web Application        | Client-Server Application         |
| ---------------------- | --------------------------------- |
| Browser-based          | Installed application             |
| Tested across browsers | Tested across client/server setup |
| URL access             | Dedicated server communication    |

---

**37. Difference between product-based and project-based testing.**

| Product-based                  | Project-based             |
| ------------------------------ | ------------------------- |
| Product for multiple customers | Built for specific client |
| Long-term enhancement          | Fixed requirements        |
| Example: Microsoft Office      | Banking project           |

---

**38. Explain maintenance phase activities.**

* Activities after deployment:

  * Bug fixing
  * Enhancements
  * Performance improvements
  * Security updates
  * Regression testing

---

**39. What is CMM level?**

* CMM (Capability Maturity Model) measures software process maturity.

* Levels:

  * Initial
  * Managed
  * Defined
  * Quantitatively Managed
  * Optimizing

---

* Common testing documents:

  * Requirement documents

  * RTM

  * Test Summary Report
