
# CUCUMBER / BDD – Interview Answers

---

**1. What is Cucumber and why is it used?**

* Cucumber is a BDD (Behavior Driven Development) automation tool used to write test scenarios in simple English language using Gherkin syntax.

* It is used because:

  * Business users can understand the test cases.
  * Improves collaboration between Developers, QA, and Business teams.
  * Makes automation scripts more readable and maintainable.
  * Supports Selenium, TestNG, JUnit, etc.

* Example:

```gherkin
Feature: Login

Scenario: Valid Login
Given user is on login page
When user enters valid credentials
Then user should login successfully
```

---

**2. Explain BDD framework architecture.**

* BDD framework architecture mainly contains:

  1. Feature Files

     * Contains scenarios written in Gherkin language.

  2. Step Definition Files

     * Contains Java methods for each Gherkin step.

  3. Runner File

     * Used to execute feature files.

  4. Hooks

     * Used for preconditions and postconditions.

  5. Utility Files

     * Reusable methods like browser setup, screenshots, waits.

  6. Test Data / Config Files

     * Stores URLs, credentials, environment data.

* Flow: Feature File → Step Definition → Selenium Actions → Result Generation

---

**3. What are feature files, step definitions, runner files, hooks, and glue code?**

* Feature File

  * Contains test scenarios written in Gherkin language.

* Step Definition

  Java methods that implement Gherkin steps.

* Example:

```java
@Given("user is on login page")
public void loginPage() {
    driver.get("url");
}
```

* Runner File

* Used to trigger execution.

* Example:

```java
@RunWith(Cucumber.class)
@CucumberOptions(features="src/test/resources")
```

* Hooks

* Used before or after scenarios.

* Example:

```java
@Before
@After
```

* Glue Code

Connects feature files with step definition files.

---

**4. Difference between Scenario and Scenario Outline.**

| Scenario            | Scenario Outline        |
| ------------------- | ----------------------- |
| Executes once       | Executes multiple times |
| Uses fixed data     | Uses multiple datasets  |
| No Examples keyword | Uses Examples table     |

* Example:

```gherkin
Scenario Outline: Login
When user enters "<username>" and "<password>"

Examples:
| username | password |
| admin    | admin123 |
| user1    | test123  |
```

---

**5. Difference between Scenario Outline and Data Tables.**

| Scenario Outline             | Data Table                             |
| ---------------------------- | -------------------------------------- |
| Used for multiple executions | Used for bulk data in single execution |
| Uses Examples                | Uses table format directly             |
| Repeats scenario             | Single scenario execution              |

* Data Table Example:

```gherkin
When user enters following details
| username | admin |
| password | admin123 |
```

---

**6. What is Background keyword?**

* Background is used to execute common steps before every scenario in a feature file.

* xample:

```gherkin
Background:
Given user launches browser
And user opens application
```

* This avoids repeating same steps in all scenarios.

---

**7. What happens if Background is not provided?**

* If Background is not used:

  * Common steps must be repeated in every scenario.
  * Feature file becomes lengthy.
  * Maintenance becomes difficult.

* Execution still works normally.

---

**8. What are Hooks in Cucumber?**

* Hooks are special blocks used to run setup or cleanup code before or after scenarios.

* Types:

  * Before Hook
  * After Hook
  * BeforeStep
  * AfterStep

* Used for:

  * Browser launch
  * Screenshot capture
  * Closing browser
  * Database connection

---

**9. Explain Before and After hooks.**

* Before Hook

* Runs before each scenario.

* Example:

```java
@Before
public void setup() {
    driver = new ChromeDriver();
}
```

* After Hook

* Runs after each scenario.

* Example:

```java
@After
public void teardown() {
    driver.quit();
}
```

---

**10. What are Cucumber tags?**

* ags are used to group and control scenario execution.

* Example:

```gherkin
@Smoke
Scenario: Login Test
```

* Uses:

  * Smoke testing
  * Regression testing
  * Selective execution

* Runner example:

```java
tags="@Smoke"
```

---

**11. How do you skip or rerun failed scenarios?**

* Skip Scenarios

* Use tags:

```java
tags="not @Skip"
```

* Rerun Failed Scenarios

* Use rerun plugin:

```java
plugin = {"rerun:target/failed.txt"}
```

* Then execute failed scenarios using:

```java
features="@target/failed.txt"
```

---

**12. Explain dryRun and strict options.**

* dryRun = true

* Checks whether all step definitions are implemented.

  * Does not execute tests.
  * Used to identify missing steps.

* strict = true

* Fails execution if undefined or pending steps exist.

* Example:

```java
@CucumberOptions(
dryRun = true,
strict = true
)
```

**13. How do you integrate Cucumber with TestNG?**

* Steps:

  1. Add Cucumber-TestNG dependency.
  2. Extend AbstractTestNGCucumberTests class.
  3. Create TestNG runner file.

* Example:

```java
public class TestRunner extends AbstractTestNGCucumberTests {
}
```

* Benefits:

  * Parallel execution
  * Better reporting
  * TestNG annotations support

**15. What language does Gherkin use?**

* Gherkin uses simple plain English language.

* It follows:

```gherkin
Given
When
Then
```

* It is business-readable and non-technical users can understand it.

---

**16. How do you run Cucumber tests in parallel?**

* Using:

  * TestNG
  * Maven Surefire Plugin
  * Parallel plugin

* Example in TestNG:

```xml
<suite parallel="tests" thread-count="2">
```

* Benefits:

  * Faster execution
  * Reduced execution time

---

**17. How does Selenium pick Cucumber feature files?**

* Selenium itself does not pick feature files.

* Cucumber Runner File identifies feature files using:

```java
features="src/test/resources/features"
```

* Then Step Definitions execute Selenium actions.

* Flow: Feature File → Step Definition → Selenium WebDriver

---

**18. Explain Cucumber framework structure.**

* Typical structure:

```text
src/test/java
    ├── stepDefinitions
    ├── runners
    ├── hooks
    ├── utilities

src/test/resources
    ├── features
    ├── config files
```

* Framework includes:

  * Feature files
  * Step definitions
  * Runner files
  * Hooks
  * Reports
  * Utilities

---

**19. Which is better for automation: Cucumber or TestNG?**

* Depends on project requirement.

* Cucumber

* Best when:

  * Business involvement is needed.
  * Readable test cases are important.
  * BDD approach is followed.

* TestNG

* Best when:

  * Pure automation framework needed.
  * Complex validations required.
  * Faster execution and flexible configurations needed.

* Real-time Answer:

  * Usually companies use: Selenium + Cucumber + TestNG together.

  * Because:

    * Cucumber gives readability.
    * TestNG gives reporting and parallel execution.
