
# Selenium Framework Concepts – Interview Answers

59. What is Page Object Model (POM)?

	* Page Object Model is a design pattern used in Selenium automation framework.

	* In POM:

		* Each webpage is created as a separate Java class.
		* Web elements and methods are maintained inside that class.

	* Example

		* LoginPage.java:

```java id="5x7kqt"
public class LoginPage
{
    WebDriver driver;

    By username = By.id("user");
    By password = By.id("pass");
    By loginBtn = By.id("login");

    public void login(String u, String p)
    {
        driver.findElement(username).sendKeys(u);
        driver.findElement(password).sendKeys(p);
        driver.findElement(loginBtn).click();
    }
}
```

	* Benefits

		* Reusability
		* Maintainability
		* Better code organization

I	* Interview Line: “POM improves framework maintainability by separating page locators and business logic.”

---

60. Advantages and disadvantages of POM.

	* Advantages

		* Easy maintenance
		* Better code reusability
		* Reduced code duplication
		* Improved readability
		* Centralized locator management

	* Disadvantages

		* More classes required
		* Initial framework setup takes time
		* Small projects may become over-engineered

* Interview Line: “POM is highly useful for large scalable automation frameworks.”

61. What is Page Factory?

	* Page Factory is an extension of POM that uses annotations to initialize web elements automatically.

	* Uses:

		* @FindBy
		* PageFactory.initElements()

	* Example

```java id="w4n2fq"
@FindBy(id="username")
WebElement user;
```

	* Initialization:

```java id="6k8vhy"
PageFactory.initElements(driver, this);
```

* Interview Line: “Page Factory simplifies POM implementation using annotations and lazy initialization.”

---

62. Explain @FindBy annotation.

	* @FindBy is used to locate elements in Page Factory model.

	* Example

```java id="q1m7tr"
@FindBy(id="login")
WebElement loginButton;
```

	* Supported Locators

		* id
		* name
		* xpath
		* css
		* className
		* linkText

	* Advantages

		* Cleaner code
		* Better readability
		* Centralized element management

---

63. What is Object Repository?

	* Object Repository is a centralized place where all web element locators are stored.

	* Can be maintained using:

		* Properties files
		* Excel
		* JSON
		* XML
		* Page classes

	* Example

```properties id="4y0lmn"
loginButton=id:login
```

	* Advantages

		* Easy maintenance
		* Reusable locators
		* Faster updates

* Interview Line: “Object Repository helps manage locators centrally and improves framework maintainability.”

---

64. Explain Data-Driven, Keyword-Driven, and Hybrid Frameworks.

* Data-Driven Framework

		* Test data separated from scripts.

		* Data Sources

			* Excel
			* CSV
			* JSON
			* Database

	* Example: Login with multiple usernames/passwords.

	* Advantage: Same script can run with multiple datasets.

* Keyword-Driven Framework: Actions maintained using keywords.

	* Example Keywords

		* click
		* type
		* login
		* select

	* Advantage: Less coding required for testers.

* Hybrid Framework

	* Is a Combination of:

		* POM
		* Data-Driven
		* Keyword-Driven

	* Most companies use Hybrid Framework.

* Interview Line: “Hybrid framework provides flexibility, scalability, and maintainability.”

67. What are recovery scenarios in Selenium?

	* Recovery scenarios are mechanisms used to recover automation execution after failures.

	* Examples

		* Re-login after session timeout
		* Refresh page if stale element occurs
		* Retry failed steps
		* Handle unexpected popups

	* Benefits

		* Improves stability
		* Reduces flaky failures

* Interview Line: “Recovery scenarios help automation continue execution even after temporary failures.”

---

68. Which scenarios cannot be automated?

	* Some scenarios are difficult or impossible to automate completely.

	* Examples

		* CAPTCHA
		* OTP verification
		* Biometric authentication
		* Hardware testing
		* Visual validation with human judgment
		* Random unpredictable UI behavior

* Interview Line: “CAPTCHA and OTP validations are usually avoided in automation because they are designed to block automated access.”

69. What are DesiredCapabilities?

	* DesiredCapabilities is used to define browser properties and configurations.

	* Used for

		* Browser name
		* Browser version
		* Platform
		* SSL certificates
		* Headless execution

	* Example

```java id="g7n3kx"
DesiredCapabilities cap =
new DesiredCapabilities();

cap.setBrowserName("chrome");
```

	* Note:	Modern Selenium mostly uses browser-specific Options classes.

	* Example:

		* ChromeOptions
		* FirefoxOptions

---

70. How do you achieve cross-browser testing?

	* By running same tests on multiple browsers.

	* Example

```java id="j2m8pz"
WebDriver driver;

if(browser.equals("chrome"))
{
    driver = new ChromeDriver();
}
else if(browser.equals("firefox"))
{
    driver = new FirefoxDriver();
}
```

	* Browsers

		* Chrome
		* Firefox
		* Edge
		* Safari

* Interview Line: “Cross-browser testing ensures application compatibility across different browsers.”

72. How do you reduce automation execution time?

	* Methods:

		* Parallel execution
		* Selenium Grid
		* Headless execution
		* Reusable methods
		* Remove unnecessary waits
		* Execute critical tests only
		* API-level validations where possible

	* Example: Run smoke tests first before full regression.

* Interview Line: “We reduce execution time mainly through parallel execution and optimized synchronization.”
