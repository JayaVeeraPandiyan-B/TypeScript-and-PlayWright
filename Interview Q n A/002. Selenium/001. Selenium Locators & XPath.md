
# Selenium Locators & XPath – Interview Answers

11. Explain all Selenium locators.

	* Selenium provides different locators to identify web elements.

		1. ID

			* Fastest and most reliable locator.

```java id="i3ijql"
driver.findElement(By.id("username"));
```

		2. Name

```java id="25rmtt"
driver.findElement(By.name("email"));
```

		3. ClassName

```java id="7jv6rm"
driver.findElement(By.className("loginBtn"));
```

		4. TagName: Used to identify HTML tags.

```java id="y0o6b8"
driver.findElements(By.tagName("a"));
```

		5. LinkText: Used for exact link text.

```java id="trr0r2"
driver.findElement(By.linkText("Login"));
```

		6. PartialLinkText: Used for partial matching.

```java id="1fz7es"
driver.findElement(By.partialLinkText("Log"));
```

		7. XPath: Most powerful locator.

```java id="t75vne"
driver.findElement(By.xpath("//input[@id='email']"));
```

		8. CSS Selector: Faster than XPath in many cases.

```java id="6q8uln"
driver.findElement(By.cssSelector("input#email"));
```

12. Difference between XPath and CSS Selector.

| XPath                               | CSS Selector                    |
| ----------------------------------- | ------------------------------- |
| Supports traversing both directions | Supports only forward direction |
| Supports functions like contains()  | No XPath functions              |
| Slower compared to CSS              | Faster                          |
| More flexible                       | Simpler syntax                  |
| Can locate using text               | Cannot directly locate by text  |

	* Example

		* XPath:

```java id="0vv57r"
//input[@id='email']
```

		* CSS:

```java id="eh5cl0"
input#email
```

---

13. Difference between absolute XPath and relative XPath.

| Absolute XPath                     | Relative XPath       |
| ---------------------------------- | -------------------- |
| Starts from root node              | Starts from anywhere |
| Starts with /                      | Starts with //       |
| Long and fragile                   | Short and reliable   |
| Breaks easily if structure changes | More stable          |

	* Example

		* Absolute XPath:

```java id="fr1rnp"
/html/body/div/input
```

		* Relative XPath:

```java id="mo3mm2"
//input[@id='username']
```

	* Interview Line: “In projects we mostly use relative XPath because it is stable and maintainable.”

---

14. Difference between single slash and double slash in XPath.

| Single Slash (/)    | Double Slash (//)   |
| ------------------- | ------------------- |
| Direct child        | Any descendant      |
| Exact path required | Searches entire DOM |
| Faster              | Flexible            |

	* Example

		* Single Slash:

```java id="i7b39f"
//div/input
```

		* Double Slash:

```java id="r0lthx"
//div//input
```

15. Explain XPath functions used in projects.

	* contains(): Used for partial attribute matching.

```java id="uqv9vm"
//input[contains(@id,'user')]
```

	* starts-with()

```java id="ncnmvl"
//input[starts-with(@id,'user')]
```

	* text()

```java id="lj7xqk"
//button[text()='Login']
```

	* normalize-space(): Removes extra spaces.

```java id="vh9o5f"
//button[normalize-space()='Submit']
```

	* last(): Gets last element.

```java id="z95mgj"
(//input[@type='text'])[last()]
```

	* position()

```java id="fgfbwo"
(//a)[position()=2]
```

16. How do you handle dynamic elements using XPath?

	* Dynamic elements change attributes dynamically during runtime.

		* We use:

			* contains()
			* starts-with()
			* relative XPath
			* parent-child relations

	* Example

		* Dynamic ID:

```html id="ylxg4k"
id="user_12345"
```

		* XPath:

```java id="n1qlsf"
//input[contains(@id,'user_')]
```

	* Interview Line: “In projects we avoid exact dynamic attributes and use contains or stable parent relationships.”

17. How do you locate nth child, parent-child, sibling, or dependency XPath elements?

	* nth child

```java id="p4f1uk"
(//input[@type='text'])[2]
```

	* Parent to Child

```java id="55l5tw"
//div[@class='form']//input
```

	* Child to Parent

```java id="pv6xw4"
//input[@id='email']/parent::div
```

	* Following Sibling

```java id="vq7xga"
//label[text()='Username']/following-sibling::input
```

	* Preceding Sibling

```java id="s9j8o8"
//input/preceding-sibling::label
```

18. When would you use XPath over CSS selectors?

	* We use XPath when:

		* Element has dynamic attributes.
		* Need text-based identification.
		* Need parent-child traversal.
		* Need sibling navigation.
		* Complex DOM structure exists.

	* Example:

```java id="jlwmx2"
//button[text()='Login']
```

	* CSS cannot directly locate using visible text.

	* linkText: Matches exact link text.

```java id="m8t8qr"

```

	* partialLinkText: Matches partial text.

| linkText      | partialLinkText |
| ------------- | --------------- |

22. How do you capture all elements from auto-suggestion dropdowns?

	* We use:

		* findElements()
		* List<WebElement>
		* Looping

	* Example

```java id="jlwmo0"
List<WebElement> options =
driver.findElements(By.xpath("//li"));

for(WebElement option : options)
{
    System.out.println(option.getText());
}
```

	* Selecting specific value

```java id="tmsx5s"
for(WebElement option : options)
{
    if(option.getText().equals("Chennai"))
    {
        option.click();
        break;
    }
}
```

# Interview Line: “We capture all suggestions using findElements and iterate through the list to select required value.”
