# TestNG Interview Questions & Answers

**1. What is TestNG and why is it used?**

* TestNG is a testing framework used in Java for automation testing. It is inspired by JUnit but provides more advanced features.

* Why TestNG is used:

  * Supports annotations
  * Supports parallel execution
  * Supports grouping of test cases
  * Supports dependency management
  * Generates detailed reports
  * Supports DataProvider for data-driven testing

* It is commonly used with Selenium for automation testing.

---

**2. Explain TestNG annotations and execution hierarchy.**

* Annotations are used to control the execution flow of test cases.

 * **Common TestNG Annotations:**

   * `@BeforeSuite`
   * `@BeforeTest`
   * `@BeforeClass`
   * `@BeforeMethod`
   * `@Test`
   * `@AfterMethod`
   * `@AfterClass`
   * `@AfterTest`
   * `@AfterSuite`

* **Execution Hierarchy:**

  1. `@BeforeSuite`
  2. `@BeforeTest`
  3. `@BeforeClass`
  4. `@BeforeMethod`
  5. `@Test`
  6. `@AfterMethod`
  7. `@AfterClass`
  8. `@AfterTest`
  9. `@AfterSuite`

---

**3. Difference between @BeforeSuite, @BeforeTest, and @BeforeClass.**

* `@BeforeSuite`

  * Executes once before the entire suite execution.
  * Used for global setup.

* Example:

  * Database connection
  * Report initialization

* `@BeforeTest`

  * Executes before the `<test>` tag in `testng.xml`.

* Example:

  * Browser setup for a test module

* `@BeforeClass`

  * Executes once before the first test method of the class.

* Example:

  * Class-level object creation

---

**4. What tasks are usually written under each annotation?**

| Annotation      | Common Usage                |
| --------------- | --------------------------- |
| `@BeforeSuite`  | Report setup, DB connection |
| `@BeforeTest`   | Browser launch              |
| `@BeforeClass`  | Page object initialization  |
| `@BeforeMethod` | Login or preconditions      |
| `@Test`         | Actual test execution       |
| `@AfterMethod`  | Logout, screenshot capture  |
| `@AfterClass`   | Close objects               |
| `@AfterTest`    | Browser close               |
| `@AfterSuite`   | Flush reports               |

---

**5. What is testng.xml and why is it used?**

* `testng.xml` is a configuration file used to control test execution in TestNG.

* Uses:

  * Execute multiple classes
  * Group execution
  * Parallel execution
  * Pass parameters
  * Include/exclude tests

* Example:

```xml
<suite name="Suite">
   <test name="Test">
      <classes>
         <class name="tests.LoginTest"/>
      </classes>
   </test>
</suite>
```
---

**6. Explain priorities in TestNG.**

* Priority decides the execution order of test methods.

* Example:

```java
@Test(priority = 1)
public void login(){}

@Test(priority = 2)
public void logout(){}
```

* Lower priority executes first.

---

**7. What happens when multiple test cases have the same priority?**

* If multiple test methods have the same priority, TestNG executes them in alphabetical order based on method name.

---

**8. Can priority values be negative?**

* Yes. TestNG supports negative priority values.

* Example:

```java
@Test(priority = -1)
```

* Negative priority executes before zero or positive priorities.

---

**9. Explain dependsOnMethods and dependsOnGroups.**

* **dependsOnMethods**

* Used when one test depends on another method.

* Example:

```java
@Test
public void login(){}

@Test(dependsOnMethods="login")
public void dashboard(){}
```

* **dependsOnGroups**

* Used when a test depends on an entire group.

* Example:

```java
@Test(groups="smoke")
public void test1(){}

@Test(dependsOnGroups="smoke")
public void test2(){}
```
---

**10. How do you skip test cases conditionally?**

* Using `SkipException`.

* Example:

```java
if(condition){
   throw new SkipException("Skipping test");
}
```

* Used when:

  * Environment issue
  * Data unavailable
  * Feature disabled
---

**11. How do you rerun failed test cases?**

* **Method 1:**

* Use `testng-failed.xml`

* After execution, TestNG automatically creates:

```text
test-output/testng-failed.xml
```

* Run this XML to rerun failed tests.

* **Method 2:**

* Use Retry Analyzer.

* Example:

```java
public class Retry implements IRetryAnalyzer
```
---

**12. Explain invocationCount and threadPoolSize.**

* **invocationCount:** Runs the same test multiple times.

* Example:

```java
@Test(invocationCount = 5)
```

* **threadPoolSize:** Runs multiple invocations in parallel.

* Example:

```java
@Test(invocationCount = 5, threadPoolSize = 2)
```

* Useful for:

  * Load testing
  * Repeated execution

---

**13. What are TestNG listeners?**

* Listeners are interfaces used to monitor and customize test execution.

* Common listeners:

  * `ITestListener`
  * `ISuiteListener`
  * `IInvokedMethodListener`

* Uses:

  * Capture screenshots
  * Generate reports
  * Logging
  * Custom reporting

---

**14. Explain @Listeners annotation.**

* `@Listeners` is used to attach listener classes to test classes.

* Example:

```java
@Listeners(TestListener.class)
public class LoginTest
{
}
```

* It automatically triggers listener methods during execution.

---

**15. Difference between hard assert and soft assert.**

| Hard Assert               | Soft Assert                        |
| ------------------------- | ---------------------------------- |
| Stops execution if failed | Continues execution even if failed |
| Uses Assert class         | Uses SoftAssert class              |
| Immediate failure         | Collects all failures              |

* Hard Assert:

```java
Assert.assertEquals(actual, expected);
```

* Soft Assert:

```java
SoftAssert sa = new SoftAssert();
sa.assertEquals(actual, expected);
sa.assertAll();
```

* `assertAll()` is mandatory in Soft Assert.

---

**16. What are DataProviders and why are they used?**

* DataProvider is used for data-driven testing.

* It passes multiple sets of data to the same test method.

* Example:

```java
@DataProvider(name="loginData")
public Object[][] data(){
   return new Object[][]{
      {"admin","123"},
      {"user","456"}
   };
}

@Test(dataProvider="loginData")
public void login(String uname, String pwd)
{
}
```

---

**17. How do you execute tests in parallel?**

* Using `parallel` attribute in `testng.xml`.

* Example:

```xml
<suite name="Suite" parallel="methods" thread-count="3">
```

* Parallel Types:

  * methods
  * classes
  * tests

* Benefits:

  * Faster execution
  * Supports cross-browser testing

---

**18. How do you group and exclude tests?**

* Grouping:

```java
@Test(groups="smoke")
```

* Include/Exclude in XML:

```xml
<groups>
   <run>
      <include name="smoke"/>
      <exclude name="regression"/>
   </run>
</groups>
```

---

**19. How do you capture screenshots only for failed tests?**

* Using `ITestListener`.

* Inside `onTestFailure()` method:

```java
public void onTestFailure(ITestResult result)
{
   TakesScreenshot ts = (TakesScreenshot)driver;
}
```

* This captures screenshots only when test fails.

---

**20. How do you ensure dependent tests execute even if previous tests fail?**

* Use:

```java
alwaysRun = true
```

* Example:

```java
@Test(dependsOnMethods="login", alwaysRun=true)
```

Even if `login` fails, dependent test executes.

---

**21. How do you execute repeated test runs?**

* Using invocationCount:

```java
@Test(invocationCount = 10)
```

* Using XML:

* You can execute the suite multiple times through CI/CD tools like Jenkins.

* Used for:

  * Stability testing
  * Flaky test identification
  * Repeated validation
