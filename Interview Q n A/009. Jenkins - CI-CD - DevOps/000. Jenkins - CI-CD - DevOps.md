
# Jenkins / CI-CD / DevOps Interview Answers

**1. What is Jenkins and why is it used?**

* Jenkins is an open-source automation tool mainly used for Continuous Integration (CI) and Continuous Delivery/Deployment (CD).

* Why Jenkins is used:

  * Automates build, test, and deployment process
  * Reduces manual effort
  * Executes automation test suites automatically
  * Integrates with tools like:

    * Selenium
    * Playwright
    * Maven
    * GitHub
    * Docker
  * Supports scheduled executions
  * Provides execution reports and notifications

* Real-time Example:

* Whenever developers push code into Git, Jenkins automatically:

  1. Pulls latest code
  2. Builds the project
  3. Runs automation scripts
  4. Generates reports
  5. Sends email notifications

---

**2. Explain CI/CD pipeline integration in automation testing**

* CI/CD means:

  * CI → Continuous Integration
  * CD → Continuous Delivery/Deployment

* Flow of CI/CD Pipeline:

  1. Developer commits code to Git
  2. Jenkins detects code changes
  3. Build is triggered automatically
  4. Maven installs dependencies
  5. Automation test cases execute
  6. Reports are generated
  7. Deployment happens if tests pass

* Benefits:

  * Faster feedback
  * Early defect detection
  * Reduced manual testing effort
  * Supports Agile methodology
  * Continuous testing

* Example:

* In Selenium automation:

  * Jenkins triggers framework execution
  * Maven runs TestNG test cases
  * Extent Reports are generated
  * Results are emailed to team

---

**3. How do you schedule Jenkins jobs?**

* In Jenkins, jobs can be scheduled using:

  * Build periodically option
  * CRON expressions

* Steps:

  1. Open Jenkins job
  2. Go to Configure
  3. Select “Build Periodically”
  4. Enter CRON expression

* Example:

```bash
H 10 * * *
```

* Meaning:

  * Executes daily at 10 AM

* Common Scheduling:

| Schedule              | CRON           |
| --------------------- | -------------- |
| Every day at midnight | `0 0 * * *`    |
| Every 15 minutes      | `*/15 * * * *` |
| Every Sunday          | `0 0 * * 0`    |

**4. How do you create Jenkins pipelines using scripts?**

* Jenkins pipelines are created using a Jenkinsfile written in Groovy scripting language.

*  Two Types:

  1. Declarative Pipeline
  2. Scripted Pipeline

* Sample Declarative Pipeline:

```groovy
pipeline {
    agent any

    stages {

        stage('Checkout') {
            steps {
                git 'https://github.com/project.git'
            }
        }

        stage('Build') {
            steps {
                bat 'mvn clean install'
            }
        }

        stage('Test') {
            steps {
                bat 'mvn test'
            }
        }
    }
}
```

* Benefits:

  * Pipeline as Code
  * Easy maintenance
  * Version controlled
  * Reusable

**5. How do you integrate Selenium or Playwright with Jenkins?**

* Selenium Integration:

  1. Create Selenium Maven project
  2. Push project into GitHub
  3. Configure Jenkins job
  4. Add Git repository URL
  5. Add Maven build command:

```bash
mvn clean test
```

  6. Jenkins executes automation scripts

* Playwright Integration:

* Install dependencies:

```bash
npm install
```

* Run tests:

```bash
npx playwright test
```

* Jenkins executes:

  * Browser automation
  * Parallel execution
  * Report generation
  * Screenshots/videos on failure

**6. How do you trigger nightly builds?**

* Nightly builds are triggered using:

  * Build periodically
  * CRON scheduling

* Example:

```bash
0 1 * * *
```

* Meaning:

  * Executes every day at 1 AM

* Why Nightly Builds are used:

  * Regression execution
  * Smoke validation
  * Stability check
  * Daily health monitoring

* Real-time Example:

* Every night Jenkins:

  * Pulls latest code
  * Executes regression suite
  * Sends execution report to QA team

**7. How do you send execution reports/emails after execution?**

* Jenkins uses:

  * Email Extension Plugin
  * Post-build actions

* Steps:

  1. Install Email Extension Plugin
  2. Configure SMTP server
  3. Add “Editable Email Notification”
  4. Attach reports/logs

* Common Reports:

  * Extent Reports
  * Allure Reports
  * TestNG Reports

* Email Contains:

  * Build status
  * Passed/Failed count
  * Error logs
  * Execution report link

* Example: If regression fails, Jenkins automatically emails QA and Dev teams.

**8. Explain Maven lifecycle**

* Apache Maven lifecycle is a sequence of build phases used to build and manage projects.

* Main Lifecycles:

  1. Clean
  2. Default
  3. Site

* Important Phases:

| Phase    | Purpose                       |
| -------- | ----------------------------- |
| validate | Validate project              |
| compile  | Compile source code           |
| test     | Execute test cases            |
| package  | Create JAR/WAR                |
| install  | Install into local repository |
| deploy   | Deploy to remote repository   |

* Common Command:

```bash
mvn clean install
```

* Meaning:

  * Cleans old files
  * Compiles code
  * Executes tests
  * Creates build

**9. Explain Surefire plugin**

* Surefire plugin is a Maven plugin used to execute test cases.

* Mostly used for:

  * TestNG
  * JUnit

* Example:

```xml
<plugin>
  <artifactId>maven-surefire-plugin</artifactId>
</plugin>
```

* Responsibilities:

  * Executes test classes
  * Generates reports
  * Supports parallel execution
  * Supports suite XML execution

* Real-time Example:

* When Jenkins runs:

```bash
mvn test
```

* Surefire plugin executes all automation tests.

**10. What are build tools like Maven and Ant?**

* Build tools automate:

  * Compilation
  * Dependency management
  * Test execution
  * Packaging

* Maven

* Features:

  * Dependency management
  * pom.xml configuration
  * Plugin support
  * Easy integration with Jenkins

* Ant

* Features:

  * XML-based build tool
  * Uses build.xml
  * More manual configuration

* Difference:

| Maven                           | Ant                              |
| ------------------------------- | -------------------------------- |
| Convention-based                | Script-based                     |
| Dependency management available | No default dependency management |
| Easier                          | More manual                      |

**11. What is Azure DevSecOps and how is it used in automation?**

* Azure DevOps is a Microsoft platform used for:

  * CI/CD
  * Repository management
  * Test management
  * Deployment pipelines

* DevSecOps means: Development + Security + Operations

* Usage in Automation:

  * Trigger automation execution
  * Integrate Selenium/Playwright
  * Manage pipelines
  * Store test artifacts
  * Secure deployments

* Azure Pipeline Flow:

  1. Code commit
  2. Build trigger
  3. Automation execution
  4. Security validation
  5. Deployment

* Benefits:

  * End-to-end automation
  * Cloud integration
  * Secure CI/CD pipelines
