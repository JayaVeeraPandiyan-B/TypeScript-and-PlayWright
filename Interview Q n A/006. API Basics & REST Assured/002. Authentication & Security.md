# Authentication & Security — Interview Answers

**1. What is authentication and authorization?**

* **Authentication:** Authentication verifies the identity of a user or system.

  * Example:

    * Username and password login
    * Token validation

  * Question answered:

```text id="12pp7z"
Who are you?
```

---

* **Authorization:** Authorization determines what the authenticated user is allowed to access.

  * Example:

    * Admin access
    * Read-only access

  * Question answered:

```text id="9shm6r"
What are you allowed to do?
```

---

**2. Difference between authentication and authorization.**

| Authentication    | Authorization                |
| ----------------- | ---------------------------- |
| Verifies identity | Verifies permissions         |
| Happens first     | Happens after authentication |
| Uses credentials  | Uses roles/permissions       |
| Example: Login    | Example: Access control      |

  * Example:

    * User logs in successfully → Authentication
    * User accesses admin dashboard → Authorization

---

**3. Explain different API authentication mechanisms.**

  * Common API authentication methods:

| Authentication Type  | Description                    |
| -------------------- | ------------------------------ |
| Basic Authentication | Username and password          |
| Bearer Token         | Access token-based             |
| OAuth 2.0            | Secure delegated authorization |
| JWT                  | Token containing user info     |
| API Key              | Unique application key         |
| OAuth Bearer Token   | Temporary secure token         |

  * These methods protect APIs from unauthorized access.

---

**4. What is Basic Authentication?**

* Basic Authentication sends username and password encoded in Base64 format.

  * Header example:

```bash id="8icxcz"
Authorization: Basic dXNlcjpwYXNz
```

  * Advantages: Simple implementation

  * Disadvantages: Less secure if HTTPS not used

  * Usually used in:

    * Internal systems
    * Simple APIs

---

**5. What is Bearer Token Authentication?**

* Bearer Token authentication uses access tokens instead of username/password for every request.

  * Example:

```bash id="l4ckmu"
Authorization: Bearer eyJhbGciOi...
```

  * Advantages:

    * More secure
    * Token expiry supported
    * Common in REST APIs

---

**6. What is OAuth 2.0?**

* OAuth 2.0 is an authorization framework that allows third-party applications to access resources securely without exposing user credentials.

  * Example:

    * Login with Google
    * Login with Facebook

  * OAuth flow:

    1. User logs in
    2. Authorization granted
    3. Access token generated
    4. Token used for API access

  * Advantages:

    * Secure
    * Token expiration
    * Scalable

---

**7. What is JWT (JSON Web Token)?**

* JWT is a compact token format used for secure data transmission.

  * Structure:

```text id="jlwmra"
Header.Payload.Signature
```

  * Example:

```text id="8e6mr9"
eyJhbGciOiJIUzI1NiIsInR5cCI...
```

  * JWT contains:

    * User details
    * Expiration time
    * Roles/permissions

  * Advantages:

    * Stateless authentication
    * Lightweight
    * Secure

---

**8. What is API Key authentication?**

* API Key is a unique key provided to clients for accessing APIs.

  * Example:

```bash id="z7w2ij"
x-api-key: 123456789
```

  * Purpose:

    * Identify application
    * Track usage
    * Restrict unauthorized access

  * Commonly used in:

    * Public APIs
    * Third-party integrations

---

**9. How do you secure an API?**

* API security best practices:

  * Use HTTPS
  * Implement authentication and authorization
  * Use token expiration
  * Validate inputs
  * Apply rate limiting
  * Encrypt sensitive data
  * Avoid exposing sensitive information
  * Use API gateways/firewalls
  * Enable logging and monitoring
  * Prevent SQL Injection and XSS attacks

---

**10. How do you securely store credentials in Postman or automation frameworks?**

* In Postman

  * Use:

    * Environment variables
    * Secret variables

* Avoid hardcoding credentials.

---

* In Automation Frameworks

  * Use:

    * Config files
    * Environment variables
    * Jenkins credentials
    * Vault/Secret Manager

* Never store passwords directly in code repositories.

---

**11. How do you handle OAuth and Basic Authentication in automation?**

* **Basic Authentication in Automation**

  * Using Rest Assured:

```java id="ow8vut"
given()
.auth()
.basic("username","password")
.when()
.get("/users");
```

---

* **OAuth Authentication in Automation**

  * Steps:

    * Generate token
    * Store token
    * Pass token in headers

  * Example:

```java id="v6i1gc"
given()
.header("Authorization","Bearer " + token)
.when()
.get("/users");
```

---

**12. How do you handle SSL certificates in API automation?**

* SSL certificates secure communication between client and server.

  * In automation:

    * Validate SSL certificates in production
    * Relax SSL validation in test environments if required

* Example in Rest Assured:

```java id="0ojpt1"
RestAssured.useRelaxedHTTPSValidation();
```

* Purpose:

  * Avoid SSL handshake failures
  * Secure API communication
