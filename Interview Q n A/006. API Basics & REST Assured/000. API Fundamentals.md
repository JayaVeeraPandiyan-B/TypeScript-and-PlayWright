
# API Fundamentals — Interview Answers

**1. What is an API?**

* API (Application Programming Interface) is a medium that allows two software applications to communicate with each other.

* It defines:

  * How requests should be sent
  * How responses are received
  * Data formats
  * Authentication methods

* Example: A frontend application sends a request to the backend API to fetch user details.

---

**2. What is REST API?**

* REST API (Representational State Transfer) is an architectural style used for building web services.

* REST APIs:

  * Use HTTP methods like GET, POST, PUT, DELETE
  * Are stateless
  * Usually exchange data in JSON format
  * Use URLs to identify resources

* Example:

```bash
GET /users/101
```

* Used to retrieve user details.

---

**3. Difference between API and Web Service**

| API                                       | Web Service                           |
| ----------------------------------------- | ------------------------------------- |
| Allows communication between applications | A type of API that works over the web |
| Can use any protocol                      | Uses HTTP/HTTPS mainly                |
| May not require network                   | Requires network                      |
| Example: Java API                         | Example: REST/SOAP API                |

* Key Point: All Web Services are APIs, but not all APIs are Web Services.

---

**4. Difference between REST, SOAP, and GraphQL APIs**

| REST             | SOAP                   | GraphQL                  |
| ---------------- | ---------------------- | ------------------------ |
| Lightweight      | Heavy protocol         | Query-based API          |
| Uses JSON mainly | Uses XML only          | Uses JSON                |
| Faster           | More secure and strict | Fetch only required data |
| Stateless        | Protocol-based         | Flexible querying        |
| Easy to use      | Complex                | Reduces over-fetching    |

* REST: Most commonly used in modern applications.

* SOAP: Used in banking and enterprise systems.

* GraphQL: Client can request only required fields.

---

**5. What is an endpoint?**

* An endpoint is the specific URL where an API resource is accessed.

* Example:

```bash
https://api.company.com/users/101
```

* Here:
`/users/101` is the endpoint.

---

**6. What is a Base URL?**

* Base URL is the common root URL used for all API requests.

* Example:

```bash
https://api.company.com
```

* Endpoints are added after the Base URL.

* Example:

```bash
https://api.company.com/users
```

---

**7. What is JSON?**

* JSON (JavaScript Object Notation) is a lightweight data interchange format used in APIs.

* Example:

```json
{
  "id": 101,
  "name": "John"
}
```

* Advantages:

  * Human readable
  * Lightweight
  * Easy parsing
  * Widely used in REST APIs

---

**8. Explain 3-tier architecture**

* 3-tier architecture contains:

**1. Presentation Layer**

* UI/frontend
* User interaction

**2. Business Layer**

* Application logic
* API/backend processing

**3. Database Layer**

* Stores data

* Flow:

```text
Frontend → Backend/API → Database
```

* Advantages:

  * Better scalability
  * Easy maintenance
  * Improved security

---

**9. What is microservices architecture?**

Microservices architecture is a design approach where an application is divided into small independent services.

* Each service:

  * Performs a specific function
  * Has its own database
  * Can be deployed independently

* Example:

  * User Service
  * Payment Service
  * Notification Service

* Advantages:

  * Scalability
  * Faster deployment
  * Independent development

---

**10. What is API versioning?**

* API versioning is maintaining multiple versions of APIs without affecting existing clients.

* Example:

```bash
/api/v1/users
/api/v2/users
```

* Purpose:

  * Backward compatibility
  * Smooth feature upgrades

---

**11. What is Swagger/OpenAPI documentation?**

* Swagger/OpenAPI is a tool used to document and test APIs.

* Features:

  * API request/response details
  * Available endpoints
  * HTTP methods
  * Authentication details
  * Try-out feature

* Benefits:

  * Easy understanding for developers and testers
  * Simplifies API testing

---

**12. What is idempotency in APIs?**

* An API is idempotent if multiple identical requests produce the same result.

* Example:

```bash
PUT /users/101
```

* Even if called multiple times, the final result remains same.

* Idempotent methods:

  * GET
  * PUT
  * DELETE

* Non-idempotent:

  * POST

---

**13. What is pagination?**

* Pagination is the process of splitting large datasets into smaller pages.

* Example:

```bash
GET /users?page=1&limit=10
```

* Benefits:

  * Improves performance
  * Reduces response size
  * Faster loading

---

**14. What is caching in APIs?**

* Caching stores frequently used API responses temporarily to improve performance.

* Benefits:

  * Faster response
  * Reduced server load
  * Better scalability

* Example: Browser cache or CDN cache.

---

**15. What is CORS?**

* CORS (Cross-Origin Resource Sharing) is a security mechanism that controls access to resources from different domains.

* Example:

**Frontend:**

```bash
https://abc.com
```

**Backend:**

```bash
https://api.xyz.com
```

* Browser blocks requests unless CORS is enabled.

* Common header:

```bash
Access-Control-Allow-Origin
```

---

**16. What is rate limiting?**

* Rate limiting restricts the number of API requests a client can make within a time period.

* Example:

```text
100 requests per minute
```

* Purpose:

  * Prevent abuse
  * Protect servers
  * Improve stability

---

**17. What is throttling?**

* Throttling controls API traffic by slowing down excessive requests.

* Difference:

  * Rate limiting blocks requests after limit
  * Throttling slows down request processing

* Purpose:

  * Maintain server performance
  * Avoid overload
