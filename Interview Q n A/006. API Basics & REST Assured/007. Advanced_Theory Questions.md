
# Advanced / Theory API Interview Answers

**1. Explain REST API best practices.**

* REST API best practices help build scalable, secure, and maintainable APIs.

  * Best Practices

    * Use Proper HTTP Methods

      * GET → Fetch data
      * POST → Create data
      * PUT/PATCH → Update data
      * DELETE → Remove data

    * Use Meaningful Resource Names**

      * Good example:

```text
/users/101/orders
```
      * Avoid:

```text id="5rbxzr"
/getUserOrders
```

  * Use Proper Status Codes

      * Examples:

        * 200 OK
        * 201 Created
        * 400 Bad Request
        * 404 Not Found

    * Implement Versioning

      * Example:

```text id="3lm37m"
/api/v1/users
```

  * Use Pagination

      * For large datasets:

```text id="dxtx2t"
?page=1&limit=10
```

  * Secure APIs

    * HTTPS
    * Authentication
    * Authorization
    * Rate limiting

  * Validate Inputs

    * Prevent invalid data and security attacks.

  * Provide Proper Error Messages

      * Example:

```json id="mjlwm9"
{
  "error": "Invalid user ID"
}
```

**2. What are the advantages and limitations of REST APIs?**

* Advantages of REST APIs

  * Lightweight
  * Easy to understand
  * Stateless architecture
  * Supports JSON
  * Scalable
  * Platform independent
  * Faster communication

---

* Limitations of REST APIs

  * Over-fetching of data
  * Under-fetching in some cases
  * Multiple requests may be needed
  * No strict contract enforcement
  * Versioning complexity

---

**3. When would you prefer GraphQL over REST?**

* I would prefer GraphQL when:

  * Client needs only specific fields
  * Multiple resources must be fetched together
  * Reduce over-fetching and under-fetching
  * Mobile applications needing optimized data
  * Complex frontend requirements

* Example: Frontend can request only:

```graphql id="4yagv6"
{
  user {
    name
  }
}
```

* instead of complete object.

**4. What are the challenges in API automation?**

* Common challenges:

  * Dynamic data handling
  * Authentication token management
  * Environment instability
  * Third-party dependency failures
  * Complex response validation
  * Data dependency between APIs
  * Flaky tests
  * Maintaining test data
  * Version compatibility
  * Performance issues

* Solutions:

  * Reusable framework

  * Proper synchronization

**5. What is contract-first API development?**

* Contract-first development means API contract is designed before implementation.

  * Contract includes:

    * Endpoints
    * Request structure
    * Response structure
    * Data types

  * Usually defined using:

    * OpenAPI/Swagger

  * Benefits:

    * Clear communication
    * Parallel frontend/backend development
    * Better consistency

---

**6. What is consumer-driven contract testing?**

* Consumer-driven contract testing ensures provider APIs meet consumer expectations.

  * Consumer defines:

    * Required fields
    * Expected response

* Provider validates against those expectations.

  * Popular tool:

    * Pact

* Benefits:

  * Early integration issue detection
  * Safer deployments

---

**7. Explain statelessness in REST APIs.**

* Statelessness means server does not store client session information between requests.

  * Each request should contain:

    * Authentication
    * Required data

  * Example: Every request sends:

```text id="mjlwmt"
Authorization: Bearer token
```

  * Benefits:

    * Scalability
    * Simpler server design
    * Better reliability

---

**8. Explain synchronous vs asynchronous APIs.**

| Synchronous API           | Asynchronous API          |
| ------------------------- | ------------------------- |
| Client waits for response | Client does not wait      |
| Immediate response        | Delayed response          |
| Simpler flow              | Better for long processes |

---

* Synchronous Example

  * Payment validation API returns response immediately.

* Asynchronous Example

  * File processing API returns job ID and processes later.

* Benefits of async:

  * Better scalability
  * Improved performance

---

**9. What is eventual consistency in distributed systems?**

* Eventual consistency means all systems become consistent after some time instead of immediately.

  * Common in:

    * Distributed systems
    * Microservices
    * NoSQL databases

  * Example: Order service updates inventory after few seconds.

  * Benefits:

    * High availability
    * Better scalability

  * Challenge: Temporary data inconsistency.

---

**10. Explain retry mechanisms and timeout handling in APIs.**

* Retry Mechanism: Retries failed requests automatically.

  * Used for:

    * Temporary failures
    * Network issues

  * Example: Retry API 3 times before failing.

---

* Timeout Handling: Defines maximum wait time for response.

  * Types:

    * Connection timeout
    * Read timeout

  * Benefits:

    * Prevents application hanging
    * Improves reliability

  * Example in automation:

```java id="9n6ksl"
RestAssured.config()
```

---

**11. What are common security vulnerabilities in APIs?**

* Common vulnerabilities:

  * Broken authentication
  * Broken authorization
  * SQL Injection
  * Cross-Site Scripting (XSS)
  * Sensitive data exposure
  * Rate limit bypass
  * Improper input validation
  * Token leakage
  * Security misconfiguration

* Prevention:

  * HTTPS
  * Input validation
  * Token encryption
  * Secure authentication

---

**12. What is API gateway and why is it used?**

* An API gateway acts as a single entry point for multiple backend services.

  * Responsibilities:

    * Routing
    * Authentication
    * Rate limiting
    * Load balancing
    * Logging
    * Monitoring

  * Architecture:

```text id="c7pcap"
Client → API Gateway → Microservices
```

  * Benefits:

    * Centralized security
    * Better scalability
    * Simplified client communication

  * Popular API gateways:

    * Kong
    * Apigee
    * AWS API Gateway
