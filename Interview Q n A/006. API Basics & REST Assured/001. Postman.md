
# Postman – Interview Answers

**27. What is Postman and why is it used?**

* Postman is an API testing and collaboration tool used to:

  * Send API requests
  * Validate API responses
  * Automate API testing
  * Manage collections and environments
  * Generate API documentation

* Why it is used:

  * User-friendly UI
  * Supports REST and SOAP APIs
  * Easy automation and debugging
  * Supports CI/CD integration

---

**28. Explain collections, workspaces, environments, and variables**

* Collections

  * Group of API requests saved together.

* Example:

  * User APIs collection
  * Payment APIs collection

* Workspaces

  * Shared collaboration area for teams.

* Environments

  * Store environment-specific values.

* Example:

  * Dev URL
  * QA URL
  * Prod URL

* Variables

  * Dynamic reusable values.

* Example:

```text
{{baseUrl}}
{{token}}
```

---

**29. Difference between Global, Environment, and Collection variables**

| Variable Type        | Scope                | Usage                                |
| -------------------- | -------------------- | ------------------------------------ |
| Global Variable      | Entire Postman       | Common values across all collections |
| Environment Variable | Specific environment | Dev/QA/Prod specific values          |
| Collection Variable  | Specific collection  | Values used within one collection    |

* Example:

  * Global → companyName
  * Environment → qaBaseUrl
  * Collection → authToken

**30. How do you import/export collections?**

* Import

  * Click Import
  * Upload JSON collection file or paste URL

* Export

  * Open collection
  * Click Export
  * Save as JSON file

* Used for:

  * Sharing APIs across teams
  * Backup and version control

---

**31. Explain pre-request scripts and test scripts**

* Pre-request Script

* Runs before API request execution.

* Used for:

  * Generate token
  * Create dynamic data
  * Set variables

* Example:

```javascript id="x9p3ku"
pm.environment.set("id", Math.random());
```

* Test Script

* Runs after receiving response.

* Used for:

  * Validate response
  * Store values
  * Assertions

* Example:

```javascript id="n2lf3x"
pm.test("Status code is 200", function () {
    pm.response.to.have.status(200);
});
```

---

**32. What is Collection Runner?**

* Collection Runner is used to execute multiple API requests automatically in sequence.

* Features:

  * Run complete collection
  * Data-driven execution
  * Generate reports
  * Run iterations using CSV/JSON data

---

**33. What is Newman?**

* Newman is the command-line runner for Postman collections.

* Used for:

  * Running collections from terminal
  * CI/CD integration
  * Automated execution in Jenkins/GitHub Actions

* Example:

```bash id="yc7f7d"
newman run collection.json
```

---

**34. How do you automate API testing using Postman?**

* Steps:

  1. Create API requests
  2. Add assertions in test scripts
  3. Store dynamic variables
  4. Use Collection Runner/Newman
  5. Integrate with CI/CD tools

* Automation mainly uses:

  * JavaScript assertions
  * Collection Runner
  * Newman

**35. How do you add headers, query params, and payloads?**

* Headers

* Added in Headers tab.

* Example:

```text
Content-Type: application/json
Authorization: Bearer token
```

* Query Parameters

* Added in Params tab.

* Example:

```bash id="2fyb0m"
/users?country=India
```

* Payloads

* Added in Body section.

* Example JSON:

```json id="f4j9xh"
{
  "name":"John"
}
```

---

**36. How do you validate response status codes?**

* Using test scripts:

* Example:

```javascript id="qz3v4o"
pm.response.to.have.status(200);
```

Or:

```javascript id="c0q8hk"
pm.test("Validate status", function () {
    pm.expect(pm.response.code).to.eql(200);
});
```

**37. How do you store credentials securely?**

* Best practices:

  1. Use environment variables
  2. Avoid hardcoding credentials
  3. Use secret variables
  4. Exclude sensitive files from Git
  5. Use Postman Vault for secrets

---

**38. How do you save mock responses?**

* Using Mock Servers:

  1. Create collection
  2. Add example responses
  3. Generate mock server URL
  4. Use mock endpoint for testing

* Useful when:

  * Backend is unavailable
  * Frontend testing needed

**39. What are Mock Servers and Monitors?**

* Mock Server

* Simulates API responses without real backend.

* Monitor

* Scheduled automated execution of collections.

* Used for:

  * Availability checks
  * Regression validation
  * API health monitoring

**41. How do you integrate Postman into CI/CD pipelines?**

* Using Newman with CI tools like:

  * Jenkins

* Example:

```bash id="6qly4o"
newman run collection.json
```

* Pipeline flow:

  * Build → Deploy → Run API tests → Generate report

---

**42. How do you test SOAP APIs using Postman?**

* Steps:

  1. Select POST method
  2. Add SOAP XML request in Body
  3. Add Content-Type:

```text
text/xml
```

  4. Send request
  5. Validate XML response

* Postman supports:

  * SOAP headers
  * XML body validation

---

**43. How do you test APIs requiring VPN access?**

* Steps:

  1. Connect to VPN first
  2. Verify endpoint accessibility
  3. Configure proxy if needed
  4. Execute APIs normally in Postman

* Common issue:

  * Connection timeout if VPN disconnected

---

**44. How do you upload files using Postman?**

* Steps:

  1. Select POST request
  2. Go to Body → form-data
  3. Select File type
  4. Upload file
  5. Send request

* Used for:

  * Image upload
  * Document upload
  * Attachment APIs
