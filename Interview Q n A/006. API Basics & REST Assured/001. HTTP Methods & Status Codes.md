
# HTTP Methods & Status Codes — Interview Answers

**1. Explain HTTP request and HTTP response components.**

* **HTTP Request Components:** An HTTP request contains: URL / Endpoint - Specifies the API resource.

* Example:

```bash id="g8gzvg"
https://api.company.com/users
```

* **HTTP Method:** Defines the action.

* Examples:

  * GET
  * POST
  * PUT
  * DELETE

* **Headers:** Provide additional information.

Examples:

```bash id="n3flmn"
Content-Type: application/json
Authorization: Bearer token
```

  * **Request Body:** Contains data sent to server.

Example:

```json id="gwl9w2"
{
  "name": "John"
}
```

  * **Query Parameters:** Used for filtering/searching.

Example:

```bash id="8u3y5w"
/users?page=1
```

---

* **HTTP Response Components**

  1. **Status Code:** Indicates request result.

Example:

```text id="my5llx"
200 OK
```

  2. **Response Headers:** Contain metadata.

Example:

```bash id="5qvh11"
Content-Type: application/json
```

  3. **Response Body:** Contains returned data.

Example:

```json id="1ovfne"
{
  "id": 101,
  "name": "John"
}
```

---

**2. Explain HTTP methods: GET, POST, PUT, PATCH, DELETE.**

| Method | Purpose                 |
| ------ | ----------------------- |
| GET    | Retrieve data           |
| POST   | Create new resource     |
| PUT    | Update entire resource  |
| PATCH  | Update partial resource |
| DELETE | Remove resource         |

---

* **GET:** Used to fetch data.

Example:

```bash id="e76x5o"
GET /users/101
```

---

* **POST:** Used to create data.

Example:

```bash id="sqzxy3"
POST /users
```

---

* **PUT:** Updates entire resource.

Example:

```bash id="tkm7ee"
PUT /users/101
```

---

* **PATCH:** Updates only specific fields.

Example:

```bash id="y8qenp"
PATCH /users/101
```

---

* **DELETE:** Removes resource.

Example:

```bash id="r9f0wx"
DELETE /users/101
```

---

**3. Difference between GET and POST**

| GET                | POST                   |
| ------------------ | ---------------------- |
| Retrieves data     | Creates data           |
| Data sent in URL   | Data sent in body      |
| Visible in browser | More secure            |
| Limited data size  | Large payload possible |
| Idempotent         | Non-idempotent         |

---

**4. Difference between PUT and PATCH**

| PUT                       | PATCH                    |
| ------------------------- | ------------------------ |
| Updates complete resource | Updates partial resource |
| Replaces existing data    | Modifies selected fields |
| Requires full payload     | Requires partial payload |

* Example PUT:

```json id="xv8ey4"
{
  "name": "John",
  "age": 30
}
```

* Example PATCH:

```json id="smr5lc"
{
  "age": 31
}
```

---

**5. What is DELETE method used for?**

* DELETE method removes a resource from server.

  * Example:

```bash id="2rm9h2"
DELETE /users/101
```

  * Expected responses:

    * 200 OK
    * 204 No Content

---

**6. Difference between query parameters and path parameters.**

| Query Parameters             | Path Parameters           |
| ---------------------------- | ------------------------- |
| Used for filtering/searching | Used to identify resource |
| Optional                     | Usually mandatory         |
| Comes after ?                | Part of URL path          |

* Example Query Parameter:

```bash id="5w6q0t"
/users?page=1
```

* Example Path Parameter:

```bash id="5vuj8d"
/users/101
```

---

**7. Explain important HTTP status codes used in API testing.**

* HTTP status codes indicate server response result.

  * Categories:

| Range | Meaning       |
| ----- | ------------- |
| 1xx   | Informational |
| 2xx   | Success       |
| 3xx   | Redirection   |
| 4xx   | Client Error  |
| 5xx   | Server Error  |

* Commonly validated in API testing.

---

**8. Explain 200, 201, and 204 status codes.**

* 200 OK - Request successful.

  * Used for:

    * GET
    * PUT
    * PATCH

* Example:

```text id="wn8sqs"
200 OK
```

---

* 201 Created - Resource created successfully. Usually returned after POST.

Example:

```text id="0hclns"
201 Created
```

---

* 204 No Content - Request successful but no response body returned. Common for DELETE APIs.

* Example:

```text id="q0bq85"
204 No Content
```

---

**9. What is 400 Bad Request?**

* 400 means server cannot process request due to invalid client input.

* Possible reasons:

  * Missing fields
  * Invalid JSON
  * Incorrect parameters

* Example:

```json id="gkp32r"
{
  "error": "Invalid request payload"
}
```

---

**10. Difference between 401 and 403.**

| 401 Unauthorized      | 403 Forbidden         |
| --------------------- | --------------------- |
| Authentication failed | Access denied         |
| Invalid/missing token | User lacks permission |

* Example:

  * Wrong token → 401
  * Read-only user accessing admin API → 403

---

**11. What is 404 Not Found?**

* 404 means requested resource does not exist.

* Example:

```bash id="pfxr7f"
GET /users/9999
```

* If user not available:

```text id="n2t8de"
404 Not Found
```

---

**12. What is 500 Internal Server Error?**

* 500 indicates server-side failure.

* Possible reasons:

  * Application crash
  * Null pointer exception
  * Database failure

* Validation steps:

  * Check logs
  * Validate payload
  * Verify backend service

* Example:

```text id="tq8i0m"
500 Internal Server Error
```

---

**13. Difference between 502 and 503 errors.**

| 502 Bad Gateway                       | 503 Service Unavailable        |
| ------------------------------------- | ------------------------------ |
| Invalid response from upstream server | Server temporarily unavailable |
| Gateway/proxy issue                   | Server overloaded/down         |

* 502 Example

  * API gateway received invalid backend response.

* 503 Example

  * Server under maintenance or high traffic.
