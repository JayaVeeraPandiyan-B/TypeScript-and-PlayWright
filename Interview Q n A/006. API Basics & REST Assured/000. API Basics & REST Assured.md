
# API Basics & REST Assured – Interview Answers

**1. What is an API?**

* API stands for Application Programming Interface.
* It acts as a bridge between two applications, allowing them to communicate and exchange data.

* Example:

  * When a mobile app fetches weather data from a server using an API.

---

**2. Difference between API and Web Service**

| API                                       | Web Service                           |
| ----------------------------------------- | ------------------------------------- |
| Allows communication between applications | A type of API that works over the web |
| Can use different protocols               | Mainly uses HTTP/HTTPS                |
| May or may not be web-based               | Always web-based                      |
| Example: Java API                         | Example: REST API, SOAP API           |

---

**3. Difference between REST, SOAP, and GraphQL APIs**

| REST                     | SOAP                   | GraphQL                    |
| ------------------------ | ---------------------- | -------------------------- |
| Lightweight architecture | Protocol-based         | Query language             |
| Uses JSON mostly         | Uses XML only          | Uses JSON                  |
| Faster and simple        | More secure and strict | Client requests exact data |
| Easy to test             | Complex                | Reduces over-fetching      |
| Widely used              | Banking/Enterprise     | Modern frontend apps       |

---

**4. Difference between POST, PUT, PATCH, GET, and DELETE**

| Method | Purpose                 |
| ------ | ----------------------- |
| GET    | Retrieve data           |
| POST   | Create new resource     |
| PUT    | Update entire resource  |
| PATCH  | Update partial resource |
| DELETE | Remove resource         |

* Example:

  * POST → Create employee
  * PUT → Update full employee details
  * PATCH → Update only employee salary

---

**5. Explain components of HTTP request and HTTP response**

* HTTP Request Components

  1. URL
  2. HTTP Method
  3. Headers
  4. Request Body
  5. Query Parameters
  6. Authentication

* HTTP Response Components

  1. Status Code
  2. Response Body
  3. Headers
  4. Response Time

---

**6. Explain HTTP status codes**

| Status Code | Meaning                       |
| ----------- | ----------------------------- |
| 200         | Success                       |
| 201         | Resource created successfully |
| 204         | Success but no response body  |
| 401         | Unauthorized                  |
| 403         | Forbidden                     |
| 404         | Resource not found            |
| 500         | Internal server error         |
| 502         | Bad gateway                   |
| 503         | Service unavailable           |

---

**7. Difference between query parameters and path parameters**

* Path Parameter

  * Part of URL path
  * Used to identify specific resource

* Example:

```bash
/users/101
```

* Query Parameter

  * Used for filtering/searching/sorting

* Example:

```bash
/users?country=India
```

---

**8. What is server-side validation?**

* Server-side validation means validating the request data on the server before processing it.

* Examples:

  * Mandatory field validation
  * Email format validation
  * Invalid data type validation

* Purpose:

* Prevent invalid or malicious data from entering the system.

---

**9. What is 3-tier architecture?**

* 3-tier architecture contains:

* 1. Presentation Layer

  * UI/frontend

* 2. Business Layer

  * Business logic/API layer

* 3. Database Layer

  * Stores data

* Flow: Frontend → API Server → Database

---

**10. What validations are important in API testing?**

* Important validations:

  1. Status code validation
  2. Response body validation
  3. Response schema validation
  4. Header validation
  5. Authentication validation
  6. Response time validation
  7. Database validation
  8. Error message validation

---

**11. How do you test standalone and third-party integrated APIs?**

* Standalone APIs

  * Test independently
  * Validate request and response
  * Verify DB changes

* Third-party APIs

  * Validate integration flow
  * Handle token/authentication
  * Test timeout and failure scenarios
  * Use mocks/stubs if service unavailable

---

**12. What are authentication and authorization?**

* Authentication

  * Verifies who the user is

  * Example:

    * Login using username/password

* Authorization

  * Verifies what user can access

* Example:

  * Admin can delete records
  * Normal user cannot

---

**13. Explain different API authentication schemes**

1. Basic Authentication

   * Username and password

2. Bearer Token

   * Access token used in header

3. OAuth 2.0

   * Secure token-based authorization

4. API Key

   * Unique key provided to client

5. JWT Token

   * Encoded authentication token

---

**14. How do you validate API response schema and body?**

* Response Body Validation

  * Validate actual values

* Example:

```java
body("name", equalTo("John"));
```

* Schema Validation

  * Validate structure, datatype, mandatory fields

* Example:

```java
matchesJsonSchemaInClasspath("schema.json");
```

---

**15. How do you debug API failures such as 500 Internal Server Error?**

* Steps:

  1. Check request payload
  2. Verify headers and authentication
  3. Check API logs
  4. Validate request data
  5. Reproduce issue in Postman
  6. Check server/database logs
  7. Verify environment availability

---

**16. How do you handle SSL certificates in API automation?**

* In REST Assured:

```java
given().relaxedHTTPSValidation()
```

* Used for:

  * Ignoring SSL certificate validation in lower environments.

---

**17. How do you validate JSON and form-data responses?**

* JSON Response

  * Validate using JSON path

* Example:

```java
body("id", equalTo(101));
```

* Form-data

  * Validate uploaded file response
  * Validate content-type and status code

  5. Validate partial responses and errors

```json
{
 "query":"{ user{id name} }"

```

**20. What is REST Assured? Explain RequestSpecification and ResponseSpecification.**

* REST Assured

* Java library used for API automation testing.

* RequestSpecification

* Reusable request setup.

* Example:

```java
RequestSpecification req =
given().baseUri("https://api.com");
```

* ResponseSpecification

* Reusable response validations.

* Example:

```java
expect().statusCode(200);
```

---

**21. Explain POJO usage in API automation**

* POJO stands for Plain Old Java Object.

* Used for:

  * Serialization
  * Deserialization

* Benefits:

  * Cleaner code
  * Easy payload management

* Example: Convert Java object → JSON payload.

---

**22. How do you validate JSON schema programmatically?**

* Using JSON Schema Validator library.

* Example:

```java
given()
.when()
.get("/users")
.then()
.body(matchesJsonSchemaInClasspath("schema.json"));
```

---

**23. How do you handle OAuth and Basic Authentication?**

* Basic Authentication

```java
given().auth().basic("user","pass")
```

* OAuth 2.0

```java
given().auth().oauth2(token)
```

---

**24. How do you create POST requests using JSON payloads?**

* Example:

```java
String payload = "{ \"name\":\"John\" }";

given()
.header("Content-Type","application/json")
.body(payload)
.when()
.post("/users");
```

---

**25. How do you chain API requests?**

* Extract response data from one API
* Pass it to another API

* Example:

  1. Create user
  2. Extract user ID
  3. Use ID in GET/UPDATE request

* Example:

```java
int id = response.jsonPath().getInt("id");
```

---

**26. How do you handle dynamic values in APIs?**

* Dynamic values handled using:

  * JSONPath
  * Random generators
  * Environment variables
  * Tokens
  * Runtime data extraction

* Example:

```java
String token = response.jsonPath().getString("token");
```

* Used in:

  * Session IDs
  * Tokens
  * Generated IDs
  * Timestamps
