
# API Testing Concepts — Interview Answers

**1. What is API testing?**

* API testing is the process of validating APIs directly without using the UI.

  * It verifies:

    * Functionality
    * Reliability
    * Security
    * Performance
    * Response accuracy

* In API testing, requests are sent to endpoints and responses are validated.

  * Benefits:

    * Faster than UI testing
    * Detects backend issues early
    * Supports automation easily

---

**2. What validations are important in API testing?**

* Important validations include:

  * Status code validation
  * Response body validation
  * Response schema validation
  * Header validation
  * Authentication validation
  * Response time validation
  * Data validation
  * Error message validation
  * Database validation
  * Business rule validation

* Example:

  * Verify 200 status code
  * Validate JSON fields
  * Validate response time under 2 seconds

---

**3. How do you test negative scenarios in APIs?**

* Negative testing validates how APIs behave with invalid inputs.

  * Examples:

    * Invalid payload
    * Missing mandatory fields
    * Invalid authentication token
    * Invalid HTTP method
    * Large input data
    * Invalid parameter types

  * Expected validations:

    * Proper error codes
    * Proper error messages
    * No server crash

  * Example:

```json id="0o7md0"
{
  "error": "Invalid request"
}
```

---

**4. What is schema validation?**

* Schema validation checks whether API response structure matches expected format.

  * Validations include:

    * Field names
    * Data types
    * Mandatory fields
    * Nested objects

  * Example:

```json id="jlwm6q"
{
  "id": 101,
  "name": "John"
}
```

  * Here:

    * `id` should be integer
    * `name` should be string

  * Tools:

    * JSON Schema Validator
    * Rest Assured schema validation

---

**5. What is contract testing?**

* Contract testing validates whether API communication between consumer and provider follows agreed contract.

  * It verifies:

    * Request format
    * Response format
    * Field types
    * Mandatory fields

  * Purpose:

    * Avoid integration failures
    * Ensure backward compatibility

  * Popular tools:

    * Pact
    * Spring Cloud Contract

---

**6. How do you validate API response body and schema?**

* Response Body Validation

  * Validate:

    * Field values
    * Business logic
    * Response structure

  * Example:

```java id="6r1e2u"
body("name", equalTo("John"));
```

---

  * **Schema Validation:** Validate response against predefined schema.

  * Example:

```java id="1d4x3j"
matchesJsonSchemaInClasspath("schema.json");
```

---

**7. How do you validate JSON responses programmatically?**

* Using Rest Assured:

```java id="2h49k7"
given()
.when()
.get("/users")
.then()
.statusCode(200)
.body("name", equalTo("John"));
```

* Common validations:

  * Field existence
  * Data type
  * Field value
  * Array size

---

**8. How do you validate form-data responses?**

* Validate:

  * Uploaded file status
  * Response fields
  * Content type
  * Server processing result

* Example validation:

```java id="c0rm4g"
statusCode(200);
```

* Also verify:

  * File uploaded successfully
  * Correct MIME type handling

---

**9. How do you test response time and performance?**

* Validate API response time under expected limits.

* Methods:

  * Measure response duration
  * Load testing
  * Stress testing

* Tools:

  * JMeter
  * Postman
  * Rest Assured

* Example:

```java id="90e4vk"
time(lessThan(2000L));
```

* Meaning: Response should complete within 2 seconds.

---

**10. How do you debug API failures like 500 Internal Server Error?**

* Steps:

  * Check request payload
  * Verify headers and authentication
  * Check backend logs
  * Validate database connectivity
  * Verify server availability
  * Reproduce issue in Postman

* Possible causes:

  * Null pointer exception
  * Invalid data
  * Database issue
  * Server crash

---

**11. How do you test standalone APIs and third-party integrated APIs?**

* Standalone APIs

  * Test:

    * Functionality
    * CRUD operations
    * Validation rules

---

* Third-party APIs

  * Additional validations:

    * Authentication
    * Timeout handling
    * Retry mechanism
    * Error handling
    * Contract validation

  * Also use: Mock responses when external service unavailable

---

**12. How do you test GraphQL APIs?**

* GraphQL APIs use queries instead of multiple endpoints.

  * Testing involves:

    * Query validation
    * Mutation validation
    * Response validation
    * Authorization validation

  * Example query:

```graphql id="xk6phj"
query {
  user(id:101) {
    name
    email
  }
}
```

  * Advantages: Fetch only required fields

---

**13. How do you test SOAP APIs?**

* SOAP APIs use XML-based communication.

  * Validations:

    * XML request/response
    * WSDL validation
    * Status codes
    * Security headers

  * Tools:

    * Postman
    * SoapUI

  * SOAP request example:

```xml id="0tq1fy"
<soapenv:Envelope>
</soapenv:Envelope>
```

---

**14. What is mocking in API testing?**

* Mocking simulates API responses without actual backend implementation.

  * Purpose:

    * Early testing
    * Dependency removal
    * Faster testing

  * Benefits:

    * Test unavailable services
    * Simulate error scenarios

  * Example: Mock payment service response

---

**15. What are Mock Servers and Monitors?**

* Mock Server: Provides fake API responses.

  * Used when:

    * Backend not ready
    * Third-party service unavailable

---

* Monitor: Automatically checks API health periodically.

  * Validations:

    * Availability
    * Response time
    * Status codes

  * Postman Monitors can run collections automatically.

---

**16. How do you perform data-driven API testing?**

* Data-driven testing executes same API test with multiple datasets.

  * Data sources:

    * Excel
    * CSV
    * JSON
    * Database

  * Benefits:

    * Better coverage
    * Reduced duplication

  * Example: Testing login API with multiple users.

---

**17. How do you handle dynamic values in API testing?**

* Dynamic values include:

  * Tokens
  * Session IDs
  * Generated IDs

* Approach:

  * Extract response value
  * Store variable
  * Reuse in next request

* Example:

```java id="g25w59"
String token = response.jsonPath().getString("token");
```

---

**18. How do you chain API requests?**

* API chaining means using response data from one API into another API request.

  * Example flow:

    * Create user
    * Extract user ID
    * Pass user ID into update API

  * Example:

```java id="s2zhqq"
int id = response.jsonPath().getInt("id");
```

---

**19. What is server-side validation?**

* Server-side validation validates request data at backend before processing.

  * Examples:

    * Mandatory field validation
    * Data type validation
    * Business rules

  * Purpose:

    * Prevent invalid data
    * Improve security

---

**20. How do you upload files using APIs or Postman?**

* In Postman

  * Use:

    * Body → form-data
    * Select file type

---

* In Rest Assured

  * Example:

```java id="p26wzw"
given()
.multiPart("file", new File("sample.pdf"))
.when()
.post("/upload");
```

* Validations:

  * Upload success
  * File size
  * Content type

---

* Steps:

  * Use internal API endpoints
  * Validate authentication

* Challenges:

  * Network restrictions
  * SSL certificates
  * Proxy configurations

* Tools:

  * Postman
