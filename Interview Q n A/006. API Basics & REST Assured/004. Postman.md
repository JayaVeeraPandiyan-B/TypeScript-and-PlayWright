
# Postman — Interview Answers

**1. What is Postman and why is it used?**

* Postman is an API testing and collaboration tool used to:

  * Send API requests
  * Validate responses
  * Automate API testing
  * Manage API collections
  * Perform API documentation

* It supports:

  * REST APIs
  * SOAP APIs
  * GraphQL APIs

* Why it is used:

  * Easy UI
  * Faster API testing
  * Automation support
  * Team collaboration

---

**2. Explain collections, workspaces, environments, and variables in Postman.**

* Collections: A collection is a group of API requests organized together.

  * Example:

    * Login APIs
    * User APIs
    * Payment APIs

  * Benefits:

    * Easy management
    * Reusability
    * Automation support

---

* Workspaces: Workspace is a shared area where teams collaborate on APIs.

  * Types:

    * Personal workspace
    * Team workspace
    * Public workspace

---

* Environments: Environment stores variables for different environments.

  * Example:

    * DEV
    * QA
    * UAT
    * PROD

  * Example variable:

```text id="b39h4r"
baseUrl = https://qa-api.company.com
```

---

* Variables: Variables store reusable values.

  * Examples:

    * Tokens
    * URLs
    * User IDs

* Benefits:

  * Avoid hardcoding
  * Easy maintenance

---

**3. Difference between Global, Environment, and Collection variables.**

| Variable Type        | Scope                | Usage                   |
| -------------------- | -------------------- | ----------------------- |
| Global Variable      | Entire Postman       | Common values           |
| Environment Variable | Specific environment | DEV/QA/UAT configs      |
| Collection Variable  | Specific collection  | Collection-level values |

* Example:

```text id="3l3gye"
token = abc123
```

---

**4. How do you import and export collections?**

* Import Collection

  * Steps:

    * Click Import
    * Select JSON file
    * Import collection

  * Supported:

    * Collection JSON
    * Swagger/OpenAPI
    * CURL

---

* Export Collection

  * Steps:

    * Open collection
    * Click Export
    * Select format
    * Save JSON file

  * Purpose:

    * Sharing
    * Backup
    * Version control

---

**5. Explain Pre-request Scripts and Test Scripts.**

* Pre-request Script: Runs before sending request.

  * Uses:

    * Generate tokens
    * Create dynamic data
    * Set environment variables

  * Example:

```javascript id="avw7rx"
pm.environment.set("id", 101);
```

---

* Test Script: Runs after response is received.

  * Uses:

    * Validate status code
    * Validate response body
    * Store response data

  * Example:

```javascript id="v1rj1l"
pm.response.to.have.status(200);
```

---

**6. What is Collection Runner?**

* Collection Runner executes multiple API requests automatically.

  * Features:

    * Run entire collection
    * Execute data-driven tests
    * Generate reports

  * Supports:

    * CSV
    * JSON test data

  * Benefits:

    * Regression testing
    * Bulk execution

---

**7. What is Newman?**

* Newman is Postman’s command-line collection runner.

  * Used for:

    * CI/CD integration
    * Automated execution
    * HTML reporting

  * Example:

```bash id="xvwyx8"
newman run collection.json
```

  * Benefits:

    * Jenkins integration
    * Pipeline execution
    * Automation support

---

**8. How do you automate API testing using Postman?**

* Steps:

  * Create API requests
  * Add validations in Test Scripts
  * Use variables
  * Create collections
  * Execute using Collection Runner or Newman

* Example validation:

```javascript id="dztm5j"
pm.response.to.have.status(200);
```

* Automation can be integrated into:

  * Jenkins
  * GitHub Actions
  * Azure DevOps

---

**9. How do you pass headers, query parameters, and payloads in Postman?**

* Headers: Added in Headers tab.

  * Example:

```text id="0t1nmg"
Authorization: Bearer token
```

---

* Query Parameters: Added in Params tab.

  * Example:

```text id="trf1ms"
?page=1&limit=10
```

---

* Payloads: Added in Body tab.

  * Formats:

    * JSON
    * form-data
    * x-www-form-urlencoded

  * Example:

```json id="jlwmql"
{
  "name": "John"
}
```

---

**10. How do you validate response status codes in Postman?**

* Using Test Scripts:

  * Example:

```javascript id="e4v0lv"
pm.test("Status code is 200", function () {
    pm.response.to.have.status(200);
});
```

  * Other validations:

    * Response time
    * Response body
    * Headers

---

**11. How do you save mock responses?**

* Steps:

  * Create Mock Server
  * Save example responses
  * Configure request matching

* Purpose:

  * Backend unavailable
  * Early frontend testing
  * Simulate API behavior

* Benefits:

  * Faster development
  * Independent testing

---

**12. How do you generate API documentation using Postman?**

* Steps:

  * Create collection
  * Add request descriptions
  * Add examples
  * Publish documentation

* Generated docs include:

  * Endpoints
  * Methods
  * Headers
  * Sample requests/responses

* Benefits:

  * Easy API understanding
  * Team collaboration

---

**13. How do you integrate Postman collections into CI/CD pipelines?**

* Using Newman in pipelines.

  * Example Jenkins command:

```bash id="7nm80u"
newman run collection.json
```

  * Pipeline flow:

    * Build
    * Deploy
    * Run API tests
    * Generate reports

  * Benefits:

    * Continuous testing
    * Faster feedback
    * Automated regression

---

**14. Advantages of Postman compared to other API tools.**

* Advantages:

  * User-friendly UI
  * Easy API testing
  * Supports automation
  * Environment management
  * Mock server support
  * CI/CD integration
  * API documentation generation
  * Team collaboration
  * Supports REST, SOAP, GraphQL
  * Collection sharing

* Compared to tools like CURL:

  * Better visualization
  * Built-in scripting
