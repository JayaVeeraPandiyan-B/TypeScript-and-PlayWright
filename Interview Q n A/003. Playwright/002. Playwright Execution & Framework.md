
# Playwright Execution & Framework – Interview Answers

16. What are Headed and Headless Modes?

* Headless Mode

 * Browser runs in background
 * UI is not visible
 * Faster execution
 * Mostly used in CI/CD pipelines

**Example:**

```ts id="8k9f1m"
use: {
  headless: true
}
```

* Headed Mode

 * Browser UI is visible
 * Useful for debugging

**Example:**

```ts id="z3k9x1"
use: {
  headless: false
}
```

**Interview Answer:**

* “Headless mode runs the browser in the background without opening the UI, which improves execution speed. Headed mode opens the browser UI and is mainly used for debugging and observing test execution.”

17. How Do You Handle Waits and Async Operations?

* Playwright automatically handles waits using auto-waiting.

 * It waits for:

  * element visibility
  * stability
  * enabled state

* Async Operations

Playwright uses:

```ts id="q7m1dn"
async/await
```

**Example:**

```ts id="3t0p9a"
await page.click('#login');
await page.fill('#username', 'admin');
```

* Explicit Wait Example

```ts id="d2j1ss"
await page.waitForSelector('#dashboard');
```

**Interview Answer:**

* “Playwright uses async and await for handling asynchronous operations. It also provides built-in auto waiting, which automatically waits for elements to become ready before performing actions.”


21. Explain Playwright Timeouts

* Timeouts control how long Playwright waits before failing.

* Types:

 * Test timeout
 * Action timeout
 * Navigation timeout
 * Expect timeout

**Example:**

```ts id="r1x8qp"
timeout: 30000
```

**Interview Answer:**

* “Timeouts in Playwright define the maximum waiting duration for actions, navigation, assertions, or complete test execution before marking the test as failed.”

22. How Does Playwright Support Cross-Browser Testing?

* Playwright supports:

 * Chromium
 * Firefox
 * WebKit

* Same test can run on multiple browsers.

**Example:**

```ts id="f8u2wa"
projects: [
 { name: 'Chromium' },
 { name: 'Firefox' },
 { name: 'WebKit' }
]
```

**Interview Answer:**

* “Playwright supports cross-browser testing by allowing the same test scripts to run on Chromium, Firefox, and WebKit browsers.”

24. Best Practices for Playwright Framework Design

* Best practices:

 * Use Page Object Model (POM)
 * Keep reusable utilities
 * Store test data separately
 * Use proper folder structure
 * Use stable locators
 * Enable reporting and screenshots
 * Avoid hard waits
 * Maintain environment configuration

**Interview Answer:**

* “Best practices include using Page Object Model, reusable utilities, proper folder structure, stable locators, external test data management, and avoiding hard-coded waits.”

25. How Do You Handle Flaky Tests in Playwright?

* Ways to handle flaky tests:

 * Use stable locators
 * Avoid hard waits
 * Use auto waits
 * Add retries
 * Handle dynamic elements properly
 * Use proper synchronization

**Retry Example:**

```ts id="8v9ktt"

```

**Interview Answer:**

* “Flaky tests can be reduced by using stable locators, proper synchronization, auto waiting, retries, and avoiding unnecessary hard waits.”
